**Следить за релизами:** Watch → Custom → Releases в этом репо.

Полная версия на английском: [README.md](README.md).

## Принцип «receipts»

- **Со скиллом и без.** Одни и те же кейсы, одна модель, новая сессия на каждый прогон.
- **n.** Не меньше 20 прогонов на группу, прежде чем цифра попадёт в README или пост. Меньше 20 помечается как *exploratory*.
- **Разница и её неопределённость.** Доля успехов в каждой группе, разница и 95% доверительный интервал (`scripts/eval_stats.py`).
- **Near-miss.** Похожие запросы, на которых скилл не должен срабатывать. Доля ложных срабатываний публикуется рядом.
- **Сырые логи.** Все прогоны лежат в `evals/<skill>/runs/`, итог в `releases/<skill>/gate-report.json`.

Нет измеримого прироста, нет релиза. Протокол: [evals/README.md](evals/README.md).

## Установка

```bash
# Claude Code: вся коллекция как плагин
claude plugin marketplace add baurrustem/receipts
claude plugin install receipts@receipts

# Один скилл для любого агента (skills CLI); -a codex или -a openclaw для конкретного агента
npx skills add baurrustem/receipts --skill <skill-name>
```

Вручную: скопируйте папку `skills/<skill-name>/` в `~/.claude/skills/`, `~/.agents/skills/` (Codex) или `~/.openclaw/skills/`.

## Безопасность

У каждого скилла есть раздел «What it runs / sends / fetches»: какие команды он запускает, куда отправляет данные и откуда скачивает. CI проверяет каждый push: никаких бинарников, тестовых файлов внутри скиллов, `curl | sh`, скрытого Unicode; версии `npx`/`uvx` закреплены. Уязвимости сообщайте приватно: [SECURITY.md](SECURITY.md).
